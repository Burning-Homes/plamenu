## Tracking rules

- Change a checkbox only after its stated behavior and relevant focused checks pass. Wiring a feature is not acceptance.
- Record the test names/results or evidence path next to the completed item. A command matching zero tests is not evidence.
- Keep implementation and final validation separate. Use Clippy/static checks first and focused tests during implementation. Run full gates after all implementation items close; benchmarks last.
- Add an item only for an evidenced in-scope reference contract or concrete defect; record why. Do not reopen accepted families for speculative improvements.
- Keep failed checks and blockers visible until resolved; do not claim parity complete while an implementation or acceptance item remains open.
